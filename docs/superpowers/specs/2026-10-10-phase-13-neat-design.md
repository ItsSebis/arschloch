# Phase 13 design: NEAT, better play and wider training

Status: approved by the repo owner in conversation on 2026-10-10.

## Context

Phase 13 changes what the evolved players can see and what they are rewarded for (`docs/Notes.md`): who is still in the trick, predicting the other players' cards, "stable rank over rushing for President", one model for several table sizes and both decks. Project discipline for training changes (Phase 10): spec note, frozen comparison against `docs/baselines`, a measured result before anything becomes a default.

What the stagnation analysis of the user's long runs (`runs/PC`, Phase 17 roadmap entry) adds: the stall is noise- and information-limited, not capacity- or pool-limited: champion score flat from gen ~10-25 at +0.37 (5p double) / +0.62 (4p single); a single evaluation has SE 0.023-0.034 while generation-to-generation change is ~0.023 (pure noise); ~70% of the population sits in the top fitness bin so selection among near-equal genomes is random; "best generation" is lucky (best re-eval +0.415 vs held-out +0.371); hidden nodes grew 2->14 with zero gain. So Phase 13 also gets one noise-handling item (racing), which directly targets that finding.

Facts from the code: `TrainConfig` (sim/src/training/config.rs) already has champion_candidates, hall_of_fame, skill_weight; fitness is the mean role score of a genome over the same matches for every genome (common random numbers, evaluate.rs `TableSpec`, `Opponents`); NEAT inputs are the 20 features of `sim/src/strategies/neat_player/features.rs` (FEATURE_SET_VERSION 1) which `GenomeFile` requires to match exactly; `TurnContext` (sim/src/strategy.rs) has seat, hand, opponents (seat, hand_size, active, pass_ceilings), unseen_cards, own_pass_ceilings, current_combo, and is built lazily by `Strategy::needs` (Phase 19); it does NOT know who has passed in the current trick, the player count except via opponents, nor the deck variant.

Cross-repo note: the casino repo's TypeScript bot port (`packages/engine/src/arschloch-bot.ts`) implements feature set v1 and refuses other feature names. New models with new inputs therefore load in the Rust tools but not in the casino until its port is extended (separate follow-up, recorded in the roadmap; the importer already prints the feature-set-changed message).

## Design

**D1. Feature set v2 = v1 + new groups, as a prefix extension.** Feature order: `base` (the 20 existing, unchanged order and formulas) then `trick`, `hidden`, `table`. A genome file is valid when its `feature_names` equal a PREFIX of the current names and `num_inputs` equals the prefix length, so every committed genome (`neat-v1`, `neat-v2`, `@opponents` files) loads and plays bit-identically (`FEATURE_SET_VERSION` stays 1: there is no new version number for the extended list; feature sets are told apart by the `feature_names` that `GenomeFile` records, which must be a prefix of this build's `FEATURE_NAMES_V2` in `neat_player/feature_set.rs`). Training takes `--features base|trick|hidden|all` (nested prefixes: base=20, +trick, +trick+hidden, all = +table) so each arm is a clean ablation with an honest genome size.
- `trick` group (who is still in the trick; needs the pass rule `final`, with `free` every active seat counts as in): `opponents_in_trick` (active opponents that have not passed this trick, / 5), `fraction_in_trick`, `i_lead_a_fresh_trick` is already `is_leading`, `all_in_trick_close` (1 if every opponent still in the trick holds <= 2 cards), `min_hand_in_trick` (smallest hand among opponents still in the trick, scaled), `last_to_act_in_trick` (1 if no opponent after me is still in the trick). Source: new `OpponentHand::in_trick: bool` filled by `turn_context_for`/Session from the round's trick state (engine `Round` exposes who passed; add an accessor if missing).
- `hidden` group (cheap prediction first, as the roadmap says; an auxiliary head only if these help): for each candidate play of size s and top card t, `p_win_trick` = product over the opponents still in the trick of (1 - P(opponent beats the play)), where P is built per beating group: with U unseen cards, an opponent holding h of them, a group of u unseen cards of one rank (u >= s) of which b can beat the top card t, the hypergeometric tail `sum_{k>=s} (C(u,k) - C(u-b,k)) C(U-u,h-k) / C(U,h)` (for s = 1 the beater cards are pooled into one group, `1 - prod_{j<h} (U - m - j)/(U - j)`); the groups of one opponent are combined as independent (`1 - prod_g (1 - P_g)`), the opponents' hands are treated as independent, and an opponent whose pass ceiling proves it cannot beat the play contributes 0; 1 when nobody is in the trick, 0 for a pass. `expected_beaters` = the expected number of cards each opponent in the trick holds in beating groups (for s >= 2 only the groups it holds in force count), summed over the opponents and divided by 52 (not a count of groups). `my_unbeatable_fraction` = the share of the cards left in my hand after the candidate that lie in a rank group no unseen group of at least its size can beat. (`p_keep_lead_next` was dropped.) All exact functions of the existing counts/masks (Phase 19 `TurnSummary` bitmasks); deterministic f64.
- `table` group: `player_count` ((n-3)/3), `double_deck` (0/1), `pass_rule_final` flag; needs `TurnContext.table: TableInfo { player_count, deck, pass_rule }` (new field; ~25 test literals updated mechanically).
- `ContextNeeds` gains flags for the new context parts; neat's `needs` follows the enabled groups so the cheap-context optimisation of Phase 19 stays intact for v1 genomes.

**D2. Fitness variants (config `fitness`, default `mean`, old runs resume as `mean`).** `mean` (today); `risk:L` = mean role score minus L x standard deviation of the per-round role score (consistency); `tanh:K` = mean of g(s) with g(s) = tanh(K s)/tanh(K) (concave at the top: with K=4 a Vize is worth ~0.87 of a President, the roadmap's "stay safe on Vize"). Every evaluation and event reports mean AND spread (std dev of the per-round score, share of top-2 and bottom roles) whatever the fitness, so the trade-off is visible. The champion choice and held-out confirmation use the same fitness as training.

**D3. Racing (noise-aware selection, config `racing_top`, `racing_matches`, default off).** After the normal evaluation, the top fraction F of genomes by fitness is evaluated on K extra common-random-number matches (fresh seed stream) and their fitness becomes the match-weighted mean of the two estimates, which pulls lucky genomes back before selection and champion choice. The race EXPANDS: genomes just below the cutoff keep one noisy (lucky) estimate and could outrank raced ones, so while an un-raced genome has a higher fitness than the lowest pooled fitness of the raced set it is raced too (batch per round), up to a cap of 2 x ceil(F x N) genomes (at most N); the event's `racing` object records `expansion_rounds`, `raced_final` and `cap_hit`. Cost: between F x K and 2 F x K extra matches per genome of the population per generation. Targets the winner's-curse / selection-by-noise finding.

**D4. One model for several table sizes and decks (config `player_counts`, `decks`, default = today's single values).** Each training match draws (player count, deck) from the configured sets by cycling on the match index (same sequence for every genome: CRN holds; the candidate's seat is `(index / L) % players` for L settings, so every setting rotates through all its seats), builds the opponents for that table, and the genome gets `table` inputs. Fitness is the mean role score (already normalised +1..-1 per table size) over the mix; `reevaluation` and events carry per-setting columns; `cli evaluate` accepts `--player-counts`/`--decks` lists and reports every setting.

**D5. Experiment protocol (the measured result that decides defaults).** Control = the neat-v2 recipe (`docs/baselines/neat-v2/README.md`: pop 150, 120 generations, 80 matches x 8 rounds, reeval 200, champion candidates 5, weight power 0.2, pass rule final, 4 players, single deck, seeds 1,2,3). Step 0 proves the optimised build reproduces `docs/baselines/neat-v2/champion.json` byte for byte with the recorded command (a free end-to-end check of the Phase 19 bit-for-bit claim). Primary arms (4p single, 3 seeds each): A0 base; A1 base+trick; A2 base+trick+hidden; on the better of A0/A2: B1 racing, B2 risk (L=0.5), B3 tanh (K=4). Multi-size arms: M1 `all` features trained on sizes 3-6 x decks single,double against specialists (neat-v2 at 4p single, retrained v2 recipe at 3p single and 5p double). Judged on the frozen held-out battery (`cli evaluate`, seed 99+, 2000 matches x 10 rounds, the usual opponent battery, plus a mirror/head-to-head against the neat-v2 champion with the duplicate-deal skill score of Phase 12 to get luck-free numbers): an arm counts as better only when a Welch t-test between the per-seed held-out scores of the arm and of its control is significant at the two-sided 95% level (with 3 seeds that needs a large difference, so contested arms are rerun with 5 seeds; the plain 2-SE difference is printed for reference); defaults change only for such arms, otherwise the option stays opt-in and the result is documented as negative. Also report mean AND spread and the stall point of each run (the Phase 17 analysis, done with a script) so "reaches the same level faster/higher" is visible.
