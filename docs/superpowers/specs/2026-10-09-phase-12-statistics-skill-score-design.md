# Phase 12 design: statistics catalogue, new numbers, luck/skill score

Status: approved by the repo owner in conversation on 2026-10-09 (self-play is deferred to Phase 16).

## Context

The user wants (from `docs/Notes.md` "Scoring" and ROADMAP Phase 12): all statistics with their values AND a clear explanation of what each means, kept somewhere now and shown on the website later; more CLI numbers (average rank, useful passes; today only President retention is shown); and a **score that balances luck and skill**, which they find the most interesting item. Clarified in conversation:
- The luck/skill score is first a **statistic** (reported, explained). It can also be an optional extra factor in training fitness, never the single score (mean role score stays the main fitness).
- Compute it **both ways and compare**: duplicate deals (ground truth) and a cheap estimator on ordinary runs, **switchable off** so speed returns if it does not help.
- The statistics should also include an **opponent-adjusted strength rating** ("score adaption to reaction of other players").
- **Self-play / co-evolutionary training is a NEW idea: only recorded as a new roadmap phase (Phase 16) for now, not built.**

Facts from exploration: `sim::statistics::{Statistics, aggregate}` (role counts, voluntary-pass rate, role retention, `first_round_placement_variance_by_strategy`) feeds `cli/src/summary.rs::render_summary` and `cli/src/output.rs` (`RunOutput {matches, statistics}` -> results.json). `Statistics` and `MatchResult` are built by struct literal in many tests, so new data goes into NEW types, not new fields on these (except an additive optional `MatchResult` field if unavoidable). `sim::run_match(config, strategies)` draws each round's deck from one `StdRng(config.seed)` stream shared with strategy rng; `run_batch` rotates strategies by `index % n` seats. `sim::training::evaluate` has `role_score(role, n)` (+1..-1 linear), `match_seed`, common random numbers. `engine::Round` is `#[derive(Debug)]` only (not Clone). CI runs fmt, `clippy --workspace --all-targets -D warnings` (pedantic), tests on 3 OSes; history is by PR (#1, #3, #4). Existing results must stay byte-for-byte reproducible (baselines under `docs/baselines`).

## Design

### A. Statistics catalogue (single source of truth)
- New module `sim/src/stats_catalog.rs`: `StatInfo { id, name, scope (global | per_strategy | per_seat | per_table), unit, range, meaning, formula, reading (how to interpret, good/bad direction), caveats, since_phase }` and `catalog() -> &'static [StatInfo]` covering EVERY statistic (existing: role counts, voluntary pass rate, President retention per role, first-round placement variance; new ones below).
- Generated outputs from it: `docs/STATISTICS.md` (`cli stats-doc` prints it; a test fails if the committed file is stale, so it never drifts), `--explain` on the batch/evaluate commands, and a `statistics_catalog` array in results.json / `evaluate --json` next to the values. The `web` crate exposes the catalogue as JSON (`GET /api/statistics-catalog`) so the later website page needs no new backend work; the page itself is out of scope (record as a later phase item).
- Values live in a new `sim::extended_stats::ExtendedStatistics` (computed by `aggregate_extended(results, opts)`), serialized under a new `extended` key in results.json. Existing keys unchanged (additive only), `docs/BUILDING.md` JSON section updated.

### B. New numbers
1. **Average finishing rank** (1 = best) per strategy and per seat, with standard error, plus role distribution in percent.
2. **Mean role score** per strategy and per seat with SE (shows seating/position bias).
3. **Useful passes.** Definition (documented in the catalogue and `docs/RULES.md`-style example): a *voluntary* pass (a legal play existed) is *useful* if the expected finishing place of the passing seat, estimated by K same-seed rollouts of the rest of the round from that exact state, is strictly better after the pass than after the best alternative play (weakest and strongest legal play compared). Report: share of voluntary passes that are useful, mean place gain per voluntary pass, per strategy. It is sampled (`--useful-passes <rollouts K>` with `--useful-pass-sample <fraction>`, default off because rollouts cost time) and deterministic per seed. Needs `engine::Round: Clone` (add derive; check fields) and a refactor of the round loop in `match_runner.rs` into a reusable `play_out(round, strategies, ...)` shared by `run_match` and the rollouts (byte-identical results for ordinary runs, verified against committed baseline summaries).
4. **Opponent-adjusted strength rating:** Bradley-Terry fit (MM iterations) on pairwise "finished above" outcomes from every round and every pair at the table, pooled by strategy name, reported in Elo-like points (mean 0 over the field), with a bootstrap standard error over matches (resample matches, 200 times). Explained as: strength relative to THIS field, independent of the field's average; a result against stronger opponents counts for more.
5. Existing retention and pass rates get confidence bounds (Wilson interval) in the catalogue/JSON.

### C. Luck/skill score
CLI: `--skill-score off|estimate|duplicate|both`, default `off` (decide the default after measurement; recorded in the spec). With `off` there is no extra work and no extra output.
- **Duplicate deals (ground truth).** New `sim::duplicate`: `run_duplicate_batch(configs, strategies)` runs groups of k = number of strategies matches. All k matches in a group use the SAME deal seed with the strategy assignment rotated through every seat, so each strategy plays every seat's hands once. Deck shuffles come from `StdRng(mix(deal_seed, round_index))` instead of the shared play stream; this is opt-in via a `RunOptions { deal_seed: Option<u64>, record_deal_features: bool }` passed to a new `run_match_with(config, strategies, &RunOptions)` (`run_match` = defaults, so ordinary runs and all baselines are unchanged byte for byte). `--matches` must be a multiple of k in this mode (error message says so).
  - Per group g and strategy s: x̄(s,g) = mean over the k seatings of s's mean role score. **Skill score** = mean_g x̄(s,g) ± SE from the spread of x̄ across groups (luck from the deal cancels in round 1; later rounds are "luck-reduced", documented honestly because carried-over roles are partly skill).
  - **Luck share** and **variance reduction**: M = Var(single-match score) / (k · Var(x̄)) = "equivalent number of ordinary games per duplicate game"; luck share = 1 − 1/M (clamped 0..1). Both defined precisely in the catalogue.
- **Cheap estimator (works on ordinary runs and old-format data).** With `record_deal_features`, each match records the round-1 hand features per seat (count of cards >= Q, pairs, triples, quads, lowest card strength, sum of strengths; additive optional field `MatchResult.first_hand_features`, skipped when `None`). OLS (own small Gaussian-elimination solver in `sim::linalg`, no new dependencies) regresses each seat's round-1 role score on the features plus strategy fixed effects; adjusted score = actual - beta·(features - mean). Reports estimator skill ± SE and the variance it removed.
- **Comparison (when `both`):** side-by-side per strategy (plain score ±SE, duplicate skill ±SE, estimator skill ±SE), difference in standard errors, rank agreement, and a one-line verdict ("estimator recovers X% of the duplicate variance reduction at Y% of the cost"), so the user can decide whether to keep or drop the expensive mode.
- **Training hook (optional, off by default):** `TrainConfig` gets `skill_weight` (`--fitness-skill-weight w`, default 0). Fitness = `mean_role_score` (unchanged) + `w` · skill term computed on the same common-random-number deals, and `best`/`mean` events and the dashboard show the skill column. It is only wired and unit-tested here; whether a nonzero weight helps is a Phase 13 experiment. Old run directories resume with weight 0.

### D. CLI and web surface
- `render_summary` additions: a compact table (strategy | avg rank ±SE | mean score ±SE | strength rating ±SE | skill ±SE | luck share) and a section per catalogued statistic that has a value; `--explain` appends one line of meaning for each number shown. `cli evaluate` gets the same columns where they apply.
- Roadmap/docs: ROADMAP Phase 12 marked done with what was built; new **Phase 16 — Self-play and co-evolutionary training** (idea only: train populations against each other and a hall of fame, relative fitness from duplicate deals + the strength rating, fixed anchor benchmark against baselines every N generations, risks: cycling/forgetting) and a note in Phase 13 that self-play is deferred to Phase 16 (the user's intended order: Phase 13 first). Update `docs/Notes.md` handling: leave the user's file alone. New `docs/STATISTICS.md` (generated), `docs/BUILDING.md` JSON docs, `docs/ARCHITECTURE.md` (sim modules), spec `docs/superpowers/specs/2026-10-09-phase-12-statistics-skill-score-design.md` (this design, written first and committed) and a plan file `docs/superpowers/plans/2026-10-09-phase-12-statistics.md` following the repo's existing plan style.
